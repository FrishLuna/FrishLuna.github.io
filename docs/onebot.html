01 · 三种接法
怎么连

协议端在 app/server/onebot-server.js，默认端口 5760。

方式地址适合
HTTP APIPOST http://127.0.0.1:5760脚本、单次调用、不想保持连接
正向 WSws://127.0.0.1:5760本机机器人框架主动连进来
反向 WS本端连到你的框架地址AstrBot 一类支持 aiocqhttp 的框架

令牌在「面板设置 → 协议端令牌」配置；HTTP 和正向 WS 走 Authorization: Bearer 头，反向 WS 也可以直接把令牌写进 URL 的 access_token= 参数。

02 · 调用
发一个 action

和 OneBot v11 规范一致：{action, params, echo}。

curl -s http://127.0.0.1:5760 \
  -H "Authorization: Bearer 你的协议端令牌" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "send_group_msg",
    "params": { "group_id": 123456, "message": "hello" },
    "echo": "t1"
  }'

回包按 echo 配对：{ status, retcode, data, echo }。

03 · 能力
常用 action

完整的 action ↔ 内部调用对应关系以面板实验台为准——实验台里的每一项就是一个 action。

  • 消息：send_private_msg / send_group_msg / delete_msg / get_msg / get_msg_list
  • 账号：get_login_info / get_status
  • 群管理：set_group_ban / set_group_whole_ban / set_group_kick / set_group_admin / set_group_card / set_group_name / send_group_notice
  • 查询：get_group_list / get_group_member_list / get_friend_list
  • 媒体：get_image / get_record / get_file / upload_group_file / send_video
  • 互动：戳一戳、表情回应、名片赞等，实验台「互动」页签里的每一项都可直接调用。
04 · 事件
收方向

HTTP 只做调用；收到消息这类事件走 WS 推。

  • 事件实时推。群聊、私聊消息经内置协议端推给已连接的 WS 订阅方，格式按 OneBot v11 事件规范。
  • 本号自己发的消息没有回显。QQ 只推它收到的消息，所以外部框架不会响应当前账号自己发的内容——这是客户端行为，不是 bug。
  • self_id 的来路。OneBot 事件里的 self_id 要等本号发过一条消息后才能从消息记录里学出来；学到前后反向 WS 会重连换请求头，面板重启后一般半分钟内恢复。
05 · 反向 WS
接 AstrBot

反向 WS 是手写的 RFC6455 客户端（Node 全局 WebSocket 加不了自定义头）。

  • 握手头。按 aiocqhttp 的校验要求带 Authorization: Bearer、X-Self-ID、X-Client-Role: Universal 三个头。
  • 配置。面板设置 → 反向 WS 地址，填你框架的 ws 地址（令牌可并入 access_token=）。
  • 验证。get_login_info / get_status 按规范应答；连上后事件实时流入框架。
